# 后续路线与图内组合生成指导

版本：2026-09-22

## 目的

本文件是当前公开工程的后续施工指导，不是能力完成声明。目标是在既有纯整数、可复现、可审计和来源约束合同上，形成能够从多类图内关系学习语言、语境逻辑并重新组织表述的认知运行路径。

当前局部结构资格仍不等于自由对话完成；`free_dialogue_complete` 在完整资格闭合前必须保持为 `0`。

## 不可改变的边界

- 核心状态、权重、计数、排序、哈希、协议和终止判断使用纯整数或明确定义的整数定点。
- 固定输入、版本、配置和来源身份必须得到逐字节一致的规范结果；墙钟、随机数、宿主对象身份和容器插入顺序不得参与语义。
- 输入、记忆和回答必须沿 Core、Interaction Memory、Dialogue/Companion 的真实调用链运行，并保留 source、scope、revision、evidence 和 provenance。
- 不能以整句 successor、字符近邻、固定问答、来源正文直答、词表、OpenCC 或隐含模板补齐能力。
- JSONL、原始课程和外部来源只是交换或训练输入；发布产物只包含训练后的图本体、整数协议、索引、来源/许可身份、cursor、状态和 SHA。
- 数据、训练数据库、checkpoint、运行时 session 和大索引放在调用者指定的 K 盘 run root；D 盘只保留工程本体和紧凑公开样例。
- 不确定、冲突、缺少证据或结构不闭合时，保持 `UNKNOWN`、`CLARIFY`、`REPAIR` 或拒答，不猜测成确定事实。

## 学习对象

语言能力不以最上端的整句或会话记录为主要单位。主要学习对象是可组合的原子和关系：

1. 输入边界、token/span、顺序、嵌套、载体和 speaker 的结构观察。
2. Entity、Event、Property、Time、Topic、Speaker、Reference 等有明确类型的节点。
3. Cause、Precedes、Property、Mereology、Subset/Member、Alias/Refers、Similar/Antonym、Discourse、Revision、Conflict 等关系及其方向、角色、范围和证据。
4. 同一结构的多种表层实现：语序、问式、限定、数量、时态、指代、连接词、Markdown、HTML、代码、表格、引用和 OCR/ASR 结构。
5. ResponseAct、ResponsePlan、slot、structure order、realization family 与 token 片段之间的图内绑定。

整句或完整对话只作为带来源的观察样本，用于抽取上述原子、关系和生成结构；它不能成为发布时的答案索引或主要路由。

## 施工顺序

### 1. 图内语义底座

以实体、事件、属性、时间、主题和关系为中心扩展课程。训练/held-out 按实体、关系组合、来源簇和结构 family 隔离，专门检验新值和新组合，而不是记住原句。

每个训练样本至少落成：

```text
SourceRef -> Observation -> Candidate/Hypothesis -> typed bindings
         -> Evidence/Scope/Revision -> Core or Memory graph records
```

### 2. 多关系组合查询

沿同一 `QueryState` 同时接入 Core、Memory、Dialogue/Companion。frontier 只能按整数优先级、稳定 key、visited、预算和证据闭合规则扩展。查询深度由闭合条件和综合终止谓词决定，不按固定跳数或输入文本长度决定。

需要逐步覆盖：

- 单关系正向、反向和角色交换；
- 两种以上关系的链式查询；
- 属性/事件/时间与主题、指代的组合；
- 多来源支持、冲突、修订和范围隔离；
- 当前输入与历史 Memory 的合法交叉绑定；
- 缺失槽、歧义槽和冲突槽的自然澄清。

### 3. 图内生成

生成顺序固定为：

```text
选定结构/证据
 -> ResponseAct
 -> ResponsePlan
 -> typed slot binding
 -> structure order / execution
 -> realization family
 -> integer token sequence
 -> token/source/postcheck
 -> delivery
```

每个槽位必须能回指图内节点、关系、scope、来源和 realization family。表层只在最后阶段读取，并由整数 token 组合产生完整回答。没有足够结构证据时，生成自然澄清或拒答，不选择一条相似整句代替生成。

### 4. 语境和记忆

把用户输入和已交付回答分别记录为 Observation，并通过 Hypothesis、Evidence、实体/事件/时间/话题/指代关系形成 Interaction Memory。热区优先，冷记忆按结构相关性和作用域召回；跨进程恢复必须只恢复整数状态和可验证引用，不恢复隐藏文本缓存。

多轮 held-out 必须包含新实体、新主题切换、合法指代、非法指代、冲突和重启恢复。无关历史不得因为字符重叠接管当前查询。

### 5. 广域课程与增量训练

只接入许可清晰的公开来源。每轮增量训练都产生新的 run identity、课程 manifest、checkpoint、canonical SHA、held-out/negative/冲突结果和资源 receipt。训练只消费经过转换的整数记录；原始正文不进入发布图作为回答后备。

扩大范围时优先增加关系和结构 family，再增加同一 family 的实体数量。任何新数据若只能提高整句命中而不能提高图内结构消费，应标为表层覆盖，不得宣称语义能力提升。

### 6. 资格与发布

独立资格审计至少检查：

- 新实体、新关系、新组合和改写输入；
- `ANSWER`、`UNKNOWN`、`CLARIFY`、`REPAIR`、冲突和拒答；
- 三图库同轮参与、O/H/E、delivery、checkpoint/cold restore；
- 证据、来源、scope、revision 和 token postcheck 可回读；
- successor、source-body、字符近邻、词表、OpenCC 和固定 QA 路径为零；
- canonical 模型只读，包外 session，发布文件闭合且无课程原文、私有标签、密钥和绝对路径；
- 相同输入和版本的 trace、结果和 artifact identity 逐字节一致。

局部结构消费可以得到 `PASS_HELDOUT_CONSUMPTION_ONLY`，但不能直接升级为自由对话完成。只有广域组合、语境记忆、独立发布和整合评估同时闭合，才允许改变完成状态。

## 每轮工作闭环

```text
冻结目标与 split
 -> 构造/转换许可课程
 -> 编译原子、关系、证据和生成结构
 -> 在唯一 K 盘 run root 训练或增量恢复
 -> 只读 canonical 查询与 held-out 消费
 -> 记录整数 trace、receipt、SHA 和资源
 -> 独立资格审计
 -> 失败则保留 FAIL/NE/UNKNOWN 并定位最小缺口
 -> 通过才组装新的发布身份
```

不得用文档、测试数量、状态码或旁路脚本替代生产调用链结果。每个阶段必须留下可复跑的代码、图本体、课程转换结果或真实运行 artifact；没有真实消费者的协议和 fixture 不算完成。

## 选路原则

后续默认采用“原子观察 + 多关系图学习 + 组合生成 + 结构化记忆”的主线。只有当某种策略能够提高新结构/新组合的图内消费，并且保持上述边界、可审计性和回滚能力时，才允许替换当前学习策略。任何仅提高整句回放、表层命中或固定领域展示的方案，只能作为对照实验或受限产品线，不能替代主线。
