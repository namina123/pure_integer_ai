# 纯图广域语言训练路线

状态：规划完成，尚未启动本轮训练。本文是后续训练与验收的路线权威，不是能力完成声明。

## 1. 目标和判定口径

目标是把项目从“局部图结构可消费”推进到尽可能广的自然语言交流：输入能被图内语言关系解析，问题能联合 Core、Interaction Memory 和 Companion 的当前状态，回答能由图内关系重新组织并生成；多轮语境不靠回放，重启不靠恢复正文，证据不足时保持 `UNKNOWN`/`CLARIFY`/拒答。

必须同时满足以下条件才可称为自由交流候选：

1. 语言表面、语境操作和生成表面都已经物化为可组合的整数图关系，而不是仅有整句 occurrence 或外部正文。
2. 当前 QueryState 的 Core 关系、Memory O/H/E 语境和 Companion 来源身份被同一生产调用链查询并进入 ResponsePlan；每个输出槽有可审计证据。
3. 新实体、新关系组合、新问法和跨进程恢复能够通过 held-out；没有历史答案、近邻句、字符相似或外部课程回放。
4. 正式发布包是纯图运行包：无 JSONL 发布入口、回放、答案表、知识正文和发布包外资料依赖。

`free_dialogue_complete` 在全部门槛闭合前固定为 `0`。局部资格只能以具体范围命名。

## 2. 当前基线与主要缺口

当前仓库已经有整数 Core/W-08 查询、双对象/三对象结构组合、部分跨关系 witness、分层 Memory 和 Companion 接口。最近证据证明了有限对象键的消费与生成，但也明确了边界：

- Core graph-only 三类对象中有消费但不是全部生成；部分新身份出现缺槽并正确 fail-closed。
- 双对象、三对象和混合四槽结果主要证明结构绑定、消费和 ResponsePlan 引用，不证明关系语义已经学习，更不证明自然语言生成。
- 关系 witness 审计发现多个输入根仍然是互不相连的组；现有 W-06 relation pack 之间没有天然共享端点，不能把“多 pack”当作多跳图。
- 既有广域对话候选曾能回答部分公开课程问题，但回答组织仍有 surface/retrieval 依赖；它不能作为纯图语言能力基线。
- 最近便携诊断包的普通中文单轮在数分钟内无输出、工作集约 2 GiB，说明查询扩张、冷启动或候选分页仍未达到自由交流的可用性能。

因此下一轮不再增加孤立的结构探针，而从真实失败 trace 反推缺失的图内语言、关系和生成能力。

## 3. 总体路线

### 阶段 A：冻结基线和能力账本

建立一个只读 canonical 基线和能力矩阵，记录每类输入的：语言解析、Core 消费、Memory O/H/E 消费、Companion 身份、关系 witness、ResponsePlan 引用、生成、交付、耗时、峰值工作集和失败码。只保留最小专项回归，不重跑已封存 private evaluator。

每个后续 run 必须有新的 K 盘 run identity、课程 manifest、train/held-out/negative/conflict split、代码和配置身份、checkpoint、canonical SHA 与资源 receipt。失败 run 不覆盖成功 run，也不通过改分母或放宽终止门槛晋级。

### 阶段 B：图内语言表面和语境原子化

先补齐“输入如何成为图查询”的生产链，而不是先扩大知识量。训练转换器把公开语言材料拆成可组合的整数对象和关系，至少保留：

- surface atom/segment、边界、顺序、角色和变体关系；
- 实体、事件、概念、属性、时间、主题、指代及其作用域；
- 问题/陈述/否定/比较/解释/建议/澄清等 discourse operation 及其输入义务；
- 表面实现与抽象操作之间的多对多关系，包含改写、缩写、自然承接和跨语言/书写变体；
- 来源、split、revision、许可和 evidence 身份。

这些内容必须落成图内整数记录并由通用查询消费。代码只能提供 Unicode/字节边界等无语义通用机制，不能内置中文词表、问式、代词表、固定短语或语言转换规则。没有对应图证据时保持未解析。

**阶段门槛**：同一抽象操作的未见表面、未见组合和负例都能得到稳定的整数解析结果；解析结果包含原子和关系证据，不能只返回整句 key。表面证据与原始正文分离，正文不进入发布图的回答后备。

### 阶段 C：连接多关系图和组合推理

从真实共享一等端点的课程开始建立连通图，优先覆盖 entity/event/concept/topic/property、时间先后、因果、部分-整体、成员、相似/反义、角色和指代等关系族。每条 relation family 必须有独立来源和负例，但 held-out 必须测试跨 family 的真实共享端点、多跳路径、冲突和新身份；不能把不同 pack 的同名表面或整数尾号当成共享实体。

查询器采用有界多跳规划：先用当前语言解析得到候选关系，再按作用域、角色、revision 和 evidence 过滤，最后生成绑定。候选数、hop 深度、page-in 和内存均有整数预算；并列歧义继续 fail-closed。每次生成必须能指出哪条关系 witness 填了哪个槽，且所有关键输入键最终进入 ResponsePlan。

**阶段门槛**：至少 5 个关系族、20 个以上独立 held-out 组合，涵盖新实体、新拓扑、多跳、冲突和缺证据；每条都证明 Core 消费、关系 witness、生成和交付。只证明 graph key 消费的结果不能升级。

### 阶段 D：图内生成与交流操作

把“回答”从整句恢复改为 ResponsePlan 驱动的图内组织。先覆盖可泛化的操作族：直接回答、解释/定义、比较、因果说明、时间排序、总结、改写/缩写、建议、澄清、纠错、承接和有证据的拒答。每种操作由图内输入义务、关系路径、证据等级和输出槽决定；表面由训练得到的原子/组合关系生成，不能复制历史 answer surface。

回答生成必须区分：事实槽、关系槽、语境槽、来源引用槽和不确定性槽。生成前若槽位缺失、冲突或作用域不明，返回结构化的自然语言澄清/拒答路径，不用默认句或答案表掩盖缺口。

**阶段门槛**：对未见问法和关系组合进行 held-out，至少覆盖上述操作族中的 8 类；独立 rubric 评定语义相关、证据可追溯、无回放，且生成 trace 只包含当前 QueryState 的图关系。

### 阶段 E：Core、Memory O/H/E、Companion 闭环

每轮输入先进入当前 QueryState，再按权限写入 Interaction Memory：Observation 记录发生的输入/交互事实，Hypothesis 保存可废止的解释，Evidence 记录来源、scope、revision 和支持/冲突关系。回答只读取当前热区和按结构召回的冷记忆，不把历史原文或旧回答作为表面后备。

Companion 负责来源摄入、许可、原始 bytes/切片身份和可追溯引用；它是证据与来源边界，不是发布包的知识正文仓库。Core 只接收经过设计允许的、带证据的图内对象，不能把普通来源或用户陈述静默晋升为本体。

多轮课程必须包含：合法指代、主题切换、重复回忆、修订/删除、冲突、多义、无关历史、跨进程冷恢复和新资料导入。恢复只重建整数状态和可验证引用，禁止恢复隐藏文本缓存、旧 ResponsePlan 或答案回放。

**阶段门槛**：至少 30 个多轮 held-out 对话，至少 10 个跨轮追问和 5 个重启/修订/冲突场景；追问必须由当前 O/H/E 结构证据驱动，错误指代和无证据场景必须 fail-closed。

### 阶段 F：广域课程增量和性能收敛

优先复用已有公开 OASST、KdConv、Wikidata/Wikipedia、SciDB/WushuQA 及 authored 课程，但先转换为统一整数图记录；外部数据只在许可、版本、hash、来源和 split 记录齐全时进入 K 盘。可以补充公开对话、问答、代码、表格、Markdown、数学和多语言/书写变体，但每种载体都要经过同一原子/关系/生成链，不能绕过图内训练。

训练采用“失败族 -> 最小新增课程/算法差异 -> 独立 held-out -> 回归”的增量策略。只有算法或数据能力确实改变时才启动完整阶段训练；不重复同一失败 identity，不复制 canonical SQLite，不在 D 盘写大数据。

性能顺序固定为：消除全图扫描和重复正文复制 -> 稀疏 posting/关系索引 -> bounded candidate/page-in -> 热区与冷记忆分层 -> 启动解码优化 -> 仅在 profile 证明必要时迁移热点。每轮记录冷/热 p50/p95、峰值内存、候选/hop/page-in、SQLite 读取和结果 SHA；性能优化不得改变语义门。

## 4. 训练和验证闭环

每一项训练按以下顺序执行：

1. 从失败 trace 选一个能力缺口，冻结本轮目标、数据选择、split、关系族和验收 rubric。
2. 在 K 盘创建新 run root，记录来源许可、上游/本地 hash、转换参数和代码身份；先做有界规模探针。
3. 流式编译为图内整数记录，检查端点身份、关系连通性、正文不入发布 payload、train/held-out 无泄漏。
4. 启动训练/增量消费并写 checkpoint、receipt、canonical SHA；运行中只接受进程完成/失败信号，或至少 30 分钟一次的主动检查，默认 60 分钟。
5. 训练完成后用独立 session 和 held-out owner 运行自然语言输入；审计当前 QueryState 的语言、Core、O/H/E、Companion、witness、ResponsePlan、生成和交付链。
6. 若通过，保留旧 canonical 和新 artifact，记录能力范围与回归；若失败，保留完整现场并缩小路线，不把局部成功扩大为全域能力。
7. 只有所有发布门闭合后才组装独立包；发布验收使用普通终端输入，不使用 JSONL、graph key、历史 trace 或包外资料。

## 5. 分级验收矩阵

| 等级 | 证明内容 | 最低证据 | 可用表述 |
| --- | --- | --- | --- |
| L0 | 图对象和关系可读 | 整数协议、身份和只读校验 | 图存储可用 |
| L1 | 多关系 Core 消费 | 5+ 关系族、20+ held-out、witness 和缺证据拒绝 | 局部关系组合 |
| L2 | 图内语言表面与操作 | 8+ 操作族、未见表面/组合、ResponsePlan 可追溯 | 受限自然语言生成 |
| L3 | 语境与记忆 | 30 多轮、10 追问、5 冷恢复/冲突 | 受限多轮交流 |
| L4 | 广域自由交流候选 | 12 场冻结场景至少 10 场语义相关；另有 60+ 轮跨域记录，禁止回放 | 自由交流候选，非通用智能声明 |
| L5 | 独立纯图发布 | 新设备、无网络/项目、仅 CPython；无 JSONL/正文/回放；许可证、SHA、只读和 fail-closed 全通过 | 可发布纯图模型 |

任何一级失败都只保留真实的 `FAIL`/`NE`/`UNKNOWN`/`CONFLICT`，不得用文档数量、结构 key 消费或状态码替代能力。

## 6. 正式发布门

发布目录只能包含训练后图本体、整数协议/索引、来源和许可身份、模型状态、cursor、SHA/manifest 以及普通终端运行所需的代码。明确禁止：

- JSONL 发布入口、课程文件、对话记录、历史 trace、固定答案/短语表、整句 surface 回放；
- `raw_text`、知识正文、passage/document 表或任何可绕过图查询直接回答的正文副本；
- 发布包外的课程、项目源码、网络、私有评测、历史 checkpoint、外部 QA 数据库或宿主语言词表；
- 通过删文件、隐藏文件、压缩字段、清空正文或改 validator 来制造“纯图”结论。

发布前必须用新设备实测普通自然语言终端输入，复验输入表面识别、Core 关系、Memory O/H/E、Companion 证据、ResponsePlan、输出和未知/冲突拒答均来自当前图状态。不能满足时停止发布，不降低门槛。

## 7. 停止和转向条件

- 若连续两轮只增加结构组合而没有语言表面或跨关系 evidence，停止扩充 held-out，回到阶段 B/C 的图内物化。
- 若同一查询随无关历史或全图规模线性变慢，停止扩量，先做 profile 和有界规划。
- 若生成只能依赖 source body、旧答案、整句 occurrence、近邻字符或外部 JSONL，判为架构阻断，不进行发布裁剪。
- 若公开数据缺少许可/来源/身份，先换数据或记为数据阻塞，不把无 provenance 数据送入训练。
- 若某能力无法在当前资源上闭合，保留最小失败现场和下一精确实验；不把“接近”写成完成。

本路线的最终产物不是训练记录的重放器，而是一个能从图内原子、关系、语境和证据重新理解并组织回答的可迁移模型。训练、评测和发布都围绕这一条生产消费链推进。
